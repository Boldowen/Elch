Зорилго

Үндсэн дараалал:

  Найдвартай booking
  → Итгэлцэл ба аюулгүй байдал
  → Төлбөр ба review
  → Production ажиллагаа
  → Social ба өсөлт

Хэрэглэгчийн үндсэн урсгал:

  Discover → Verify → Book → Confirm → Experience → Pay → Review

3. PHASE 1 — CRITICAL SECURITY БА BOOKING FIX
============================================

3.1 Self-booking хориглох

Listing booking дээр:

  listing.hostId != travelerId

Guide booking дээр:

  guide.userId != travelerId

гэсэн шалгалт сервер талд нэмнэ.

Acceptance criteria:

  - Хэрэглэгч өөрийн listing-ийг booking хийж чадахгүй.
  - Guide өөрийгөө booking хийж чадахгүй.
  - API ойлгомжтой 400/409 алдаа буцаана.
  - Хоёр нөхцөл integration test-тэй байна.

3.2 Давхар booking хамгаалах

GuideAvailability model:

  id
  guideId
  startsAt
  endsAt
  timeZone
  status: AVAILABLE | BLOCKED

ListingInventory model:

  id
  listingId
  date
  totalUnits
  reservedUnits
  availableUnits

Overlap дүрэм:

  existing.startsAt < new.endsAt
  AND existing.endsAt > new.startsAt
  AND existing.status IN (PENDING, CONFIRMED, IN_PROGRESS)

Overlap шалгалт болон booking create-ийг нэг transaction дотор хийнэ.
PostgreSQL constraint, serializable transaction эсвэл inventory row lock ашиглана.

Acceptance criteria:

  - Ижил guide давхцсан хоёр confirmed booking авахгүй.
  - Inventory 0 үед listing booking үүсэхгүй.
  - 10 зэрэгцээ request-ийн concurrency test давна.
  - UI “Selected time is no longer available” мэдээлэл үзүүлнэ.

3.3 Booking idempotency

Client booking бүрт UUID үүсгээд дараах header явуулна:

  Idempotency-Key: <uuid>

Backend-д дараах мэдээллийг хадгална:

  key
  userId
  requestHash
  responseBody
  statusCode
  expiresAt

Acceptance criteria:

  - Ижил key, ижил request нэг booking л үүсгэнэ.
  - Ижил key, өөр payload 409 буцаана.
  - Timeout болон retry integration test-тэй байна.

3.4 Session expiration

Refresh token хүчингүй болоход:

  1. Memory session цэвэрлэнэ.
  2. Secure storage цэвэрлэнэ.
  3. Navigation-ийг Auth screen рүү reset хийнэ.
  4. “Session expired, please sign in again” мэдээлэл харуулна.

3.5 Token storage

  - Access token: зөвхөн memory.
  - Refresh token: Expo SecureStore/Keychain/Keystore.
  - Preference болон non-sensitive cache: AsyncStorage.

Logout all devices endpoint нэмнэ. Password reset хийсний дараа бүх refresh
token-ийг revoke хийнэ.

3.6 Input validation

  Booking note       — max 1000 тэмдэгт
  Message body       — max 2000 тэмдэгт
  Name               — 2–100 тэмдэгт
  Phone              — E.164 format
  Country/city       — 2–100 тэмдэгт
  Expertise          — item бүр 1–50, max 20 item
  Guide price        — positive decimal
  URL                — HTTPS only
  Image count/size   — хатуу хязгаартай


4. PHASE 2 — БҮРЭН BOOKING LIFECYCLE
====================================

4.1 Booking state machine

Шинэ төлөвүүд:

  DRAFT
  PENDING
  CONFIRMED
  IN_PROGRESS
  COMPLETED
  DECLINED
  CANCELLED_BY_TRAVELER
  CANCELLED_BY_PROVIDER
  EXPIRED
  NO_SHOW
  DISPUTED
  REFUND_PENDING
  REFUNDED

Үндсэн transition:

  Submit    — Traveler — DRAFT → PENDING
  Accept    — Provider — PENDING → CONFIRMED
  Decline   — Provider — PENDING → DECLINED
  Cancel    — Traveler — PENDING/CONFIRMED → CANCELLED_BY_TRAVELER
  Cancel    — Provider — CONFIRMED → CANCELLED_BY_PROVIDER
  Start     — System/provider — CONFIRMED → IN_PROGRESS
  Complete  — System/хоёр тал — IN_PROGRESS → COMPLETED
  Dispute   — Оролцогч — IN_PROGRESS/COMPLETED → DISPUTED

Хүчингүй transition бүр сервер дээр хориглогдоно.

4.2 Booking audit history

BookingEvent model:

  id
  bookingId
  actorId
  actorType
  fromStatus
  toStatus
  eventType
  reason
  metadata
  createdAt

Ингэснээр хэн, хэзээ, яагаад status өөрчилснийг бүрэн сэргээж чадна.

4.3 Cancellation policy

  type: FLEXIBLE | MODERATE | STRICT | CUSTOM
  freeCancellationHours
  lateCancellationPercent
  noShowPercent

Booking хийхээс өмнө cancellation deadline болон consequence-г харуулна.

4.4 Booking-bound conversation

Booking үүсэх эсвэл accept болоход traveler-provider conversation автоматаар
үүсгэнэ. Conversation дотор booking summary болон system message харуулна.

System message жишээ:

  Booking request sent
  Provider accepted the booking
  Booking time was changed
  Booking was cancelled by provider

4.5 Notification system

Notification model:

  id
  userId
  type
  title
  body
  data
  readAt
  createdAt

Notification trigger:

  - Booking created/accepted/declined/cancelled
  - Booking starting soon
  - New message
  - Guide application approved/rejected
  - Review request

4.6 Completed booking

Background job confirmed booking-ийг хугацаагаар IN_PROGRESS болон COMPLETED
болгоно. Completed үед:

  - Guide completedTrips нэмэгдэнэ.
  - Review боломж нээгдэнэ.
  - Ranking дахин тооцогдоно.

Pilot KPI:

  Booking completion rate              >= 80%
  Provider response within 2 hours     >= 80%
  Booking acceptance rate              >= 60%
  Provider cancellation                < 5%
  App crash-free sessions              >= 99%
  API 5xx rate                         < 1%
  Support response time                < 2 цаг
  Confirmed safety incident            0
  Review submission                    >= 30%
